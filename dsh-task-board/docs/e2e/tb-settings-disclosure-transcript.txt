Method
------
The user's running desktop host cannot be driven without its per-boot browser
token, so the capture boots an ISOLATED host instead of touching it:

  1. scratch home with a copy of the web profile (the profile links the local
     aggregate packages/dsh-web-all):
       rm -rf /tmp/dsh-verify
       mkdir -p /tmp/dsh-verify/profiles
       cp -a ~/.dsh/profiles/web /tmp/dsh-verify/profiles/web
       ln -s ~/.dsh/profiles/node_modules /tmp/dsh-verify/profiles/node_modules
  2. DSH_HOME=/tmp/dsh-verify dsh --profile web --port 19400 --no-open
     -> dsh web: http://127.0.0.1:19400/?token=<redacted>
     (the scratch home gets its own task-board ledger; the user's ~/.dsh is
     never written - verified: /tmp/dsh-verify/task-board/ledger-v2.json is a
     fresh 223-byte document.)
  3. headless Chrome with a CDP port, then the tokenized URL in a tab:
       "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
         --headless=new --disable-gpu --hide-scrollbars --window-size=1600,1000 \
         --remote-debugging-port=9333 --user-data-dir=/tmp/dsh-chrome-verify about:blank
  4. settings page: click 设置, then the Web 插件 section, then the 任务看板
     card header, then one topic header per capture. Page.screenshot via CDP.
